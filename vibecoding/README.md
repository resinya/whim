# Vibecoding 笔记

这里放的是**学习笔记**：记录这个仓库背后的机制，以及踩过的坑。

根目录的 [README](../README.md) 只负责回答一个问题——**这个项目是做什么的**。那些「为什么这么配」「为什么会 404」的长篇解释放在那里不合适，就统一沉淀到这个文件夹。

## 目录

| 笔记 | 讲什么 | 什么时候翻它 |
| --- | --- | --- |
| [01-monorepo-build.md](./01-monorepo-build.md) | 这个 monorepo 怎么打包：workspace、turbo 依赖图、产物从哪来 | 想搞懂 `pnpm build:naive` 到底跑了什么；构建报错时 |
| [02-vercel-deploy.md](./02-vercel-deploy.md) | 部署到 Vercel：四个设置项、`vercel.json` 逐行、常见坑 | 要上线、要改部署配置、Vercel 构建失败时 |
| [03-routing.md](./03-routing.md) | 路由：hash 与 history 的区别、404 是怎么来的、rewrite 怎么救 | 页面刷新 404、想换路由模式、不理解那条 `rewrites` 时 |

## 这些笔记的可信度分级

写笔记容易把「听说的」写成「验证过的」，所以这里明确标注来源，你自己判断该信几分：

- **✅ 读代码确认**：我打开过这个仓库对应的文件，结论有出处。
- **📖 官方文档口径**：来自 Vercel / Vite / turbo 的文档说法，没法在本仓库里直接验证。
- **⚠️ 未能实测**：受环境限制没跑起来的部分，属于推断，需要你本地验证一次。

## 一个贯穿全文的前提

这个仓库是从 `vue-vben-admin` 5.7.0 改的，很多「绕」的设计都是**上游的工程化选择**，不是这个项目特意加的。看笔记时把这句话记在心里，就不容易觉得「为什么要把简单的事情搞复杂」。
